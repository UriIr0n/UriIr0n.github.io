## Design Specificity Verdict

**LLM assessment:** This is not a template with a BI skin — it's a portfolio architected like the artifact it's selling. The homepage's own project grid has a slicer, a "showing N of M" status line, and live KPI-style counters. Every dashboard shares one shell with a collapsed "about the real project" panel, tabs, a narrated insight card, then tiles — the same rhythm a Power BI report page would have. The synthetic worlds (NovaTech, Hogwarts, Claude subscribers, NASA, Olympic delegation) carry copy that's idiomatic to each world, not decorative reskins. The "about the original project" panel doing double duty as a case study is a genuinely site-specific move. Where specificity breaks down is the connective tissue — hero, the two process carousels, and the contact block read close to what any solo technical portfolio would produce — and one dashboard's narrative text makes a cross-filtering claim the code doesn't actually honor (see Priority Issues).

**Deterministic scan:** The CLI detector returned exactly one finding — `single-font` (only Heebo used, no secondary display face). This is flagged `warning` severity and is a likely false positive here: the site deliberately standardizes on Heebo for RTL/Hebrew consistency, and the rule can't see whether size/weight contrast (which the site does use) is already carrying hierarchy.

**Visual overlays (browser evidence):** The in-page detector ran across 4 hash routes (landing, hogwarts, nasa, olympic) and surfaced far more than the CLI scan caught on markup alone: low-contrast text (3.6:1 on the skip-link, 4.4:1 on several buttons — both below WCAG AA's 4.5:1), tiny/undersized functional text (10.5–11.5px), text genuinely covered by overlapping elements (list items and headings 41–100% occluded by `.slicer-bar`/buttons), heading levels that skip h2 (h1→h4) on every route, and repeating monotonous spacing. One caveat from Assessment B: the SPA appears to keep all dashboard sections mounted in the DOM even when hash-inactive, so findings accumulated across routes rather than resetting — the landing-page findings (the default, always-visible view) are the most trustworthy at face value; later-route numbers should be spot-checked before treating as certain.

## Overall Impression

The core idea — a portfolio that behaves like the dashboards it's showcasing — is genuinely well executed and rare; the shell, chart engine, and keyboard accessibility are consistently good across all five recreations. But the polish gap sits exactly where a BI-literate visitor (the target audience) would probe hardest: one dashboard's headline stat doesn't actually respond to its own filters, contrast and text-size fail in spots a recruiter would see on first load, and the single highest-stakes action on the page — contacting Uri — silently overrides the user's own mail client. The biggest opportunity is tightening the gap between what the site *claims* about itself (interactive, cross-filtered, "just like Power BI") and what a skeptical technical reviewer can verify by clicking around.

## What's Working

1. **The homepage is itself a dashboard.** Slicer + "showing N of M" + live counters on the project grid make the portfolio's chrome match its subject matter — the single most on-brand decision on the site.
2. **Keyboard-operable cross-filtering.** Every clickable data point across all five hand-rolled chart types is a real `role="button"` with Enter/Space support and a focus tooltip — accessibility built into the charting engine itself, not bolted on.
3. **The collapsed "about the original project" panel doubling as a case study.** Stays out of the way by default, but carries genuine problem/built/tech/impact content when opened — a clever answer to "how do I prove impact without real data."

## Priority Issues

**[P1] The primary contact CTA silently overrides its own affordance**
- **Why it matters**: Every mailto link/button is intercepted to copy the address and force-open a Gmail compose tab, falling back to `mailto:` only if the popup is blocked. This is the site's single highest-stakes conversion action; a visitor without a logged-in Google session gets shunted to an unexpected screen instead of their own mail client, and even right-click/middle-click behavior becomes unpredictable.
- **Fix**: Let native `mailto:` behavior run unmodified, or offer the Gmail-compose path as an explicit secondary option next to a real mailto default.
- **Suggested command**: `/impeccable clarify`

**[P1] The recruit dashboard's headline insight contradicts its own cross-filtering claim**
- **Why it matters**: The story text invites the visitor to filter and see "הכול מסתנן יחד, בדיוק כמו ב-Power BI," but the headline gap stat is computed from unfiltered department/quota data regardless of the active filter — verified live by filtering to a specific reason and seeing the same gap number. A BI-literate visitor is exactly the audience most likely to test this claim and catch it.
- **Fix**: Recompute the headline stat from the filtered selection, or rephrase so a static stat isn't presented next to a filtered one as if both respond to the same click.
- **Suggested command**: `/impeccable harden`

**[P1] Accessibility failures on the always-visible landing view**
- **Why it matters**: The detector overlay found sub-AA contrast (3.6:1 on the skip-link, 4.4:1 on several buttons, both below the 4.5:1 text minimum) and list/heading text 41–100% covered by overlapping slicer-bar/button elements, on the default view every visitor sees first — not an edge-case route.
- **Fix**: Raise skip-link and button text contrast to ≥4.5:1; audit z-index/positioning so `.slicer-bar` and buttons don't overlap adjacent text.
- **Suggested command**: `/impeccable audit`

**[P2] No landmark navigation or correct heading structure on any dashboard page**
- **Why it matters**: `role="main"` is hardcoded only onto the home page element; every dashboard page (the actual interactive content) has zero main landmark, and headings jump h1→h4 skipping h2 on every route. A screen-reader user landmark-navigating on any dashboard finds nothing, and heading-based navigation is unreliable everywhere.
- **Fix**: Move `role="main"` onto whichever `.page.active` element is current; insert the missing h2 level in each dashboard's heading structure.
- **Suggested command**: `/impeccable harden`

**[P2] Undersized and truncated text undermines "at a glance" readability**
- **Why it matters**: Functional text runs 10.5–11.5px in several places (detector-confirmed), and category axis labels truncate to 3–4 characters at 375px width ("תל אביב" → "תל אב…") with no minimum-legibility floor — defeating the at-a-glance promise of a KPI dashboard on the device class most likely for a casual recruiter check.
- **Fix**: Raise the minimum font size for functional/axis text; switch to rotated or wrapped labels on narrow viewports instead of mid-word truncation.
- **Suggested command**: `/impeccable layout`

## Persona Red Flags

**Sam (Accessibility-Dependent User)**: No `main` landmark on any dashboard page — landmark navigation is broken on 100% of the actual interactive content. Heading levels skip h2 on every route. Sub-AA contrast confirmed on the skip-link (3.6:1) and multiple buttons (4.4:1). The sticky top nav has no active-page indicator (no `aria-current`), so a keyboard/screen-reader user can't tell which section they're in. Truncated chart axis labels are only recoverable via hover or per-element focus, not a persistent visible full-label path.

**Casey (Distracted Mobile User)**: Slicer/segment buttons measure ~32px tall at 375px — under comfortable tap-target size on exactly the interaction visitors use most. Axis-label truncation and 10.5–11.5px functional text hit hardest at mobile widths. The Gmail-new-tab contact hijack is more disruptive on mobile Safari/Chrome, where it overrides the OS's native "choose mail app" share sheet a visitor expects from a mailto link.

**Jordan (Confused First-Timer)**: Clicking a project card drops the visitor directly into a dense operational screen (4 KPIs + 2-3 charts + a sortable table, 3 tabs) with only an 11.5px gray caption hinting the tiles are clickable — easy to miss, no first-run affordance. The "who are you" role-identification prompt never changes anything downstream for that visitor's session — a one-way data collector that a first-timer might reasonably expect to personalize something.

- No `og:image` in the meta block — the most likely organic distribution path (a recruiter forwarding the link) renders as a bare text card.
- The CLI's `single-font` finding is a likely false positive given the deliberate single-face RTL/Hebrew choice and existing size/weight contrast.
- Detector methodology caveat: the SPA appears to keep inactive dashboard sections mounted in the DOM, so overlay findings accumulated across routes rather than resetting per-route; treat non-landing-route counts as needing a spot-check, not as certain.

## Questions to Consider

- If the entire pitch is "click anything, it all cross-filters, just like Power BI" — and one dashboard's own headline sentence quietly doesn't — what else in the narrative layer is decorative rather than actually wired to state?
- The site asks visitors mid-scroll to self-identify as recruiter/colleague/friend, then does nothing differently for any of the three afterward — does that widget prove Uri thinks in segments, or reveal the page hasn't decided who it's for?
- Every dashboard opens at full operational density with only a small gray caption as onboarding — is that faithful to how Uri would actually walk a manager through a new report at work, or does it assume a portfolio visitor will spend the same ramp-up minutes a paid stakeholder would?
